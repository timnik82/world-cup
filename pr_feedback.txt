## Summary

Expands the timeline from 5 sample tournaments to all 22 World Cup editions (1930–2022) and replaces the year slider with a horizontally scrollable year-button strip with prev/next navigation and dot indicators.

**Key changes:**
- **Data:** `tournaments.json` now contains all 22 World Cups (1930–2022)
- **Timeline UI:** Slider replaced with scrollable year buttons, `ChevronLeft`/`ChevronRight` nav arrows, and dot position indicators
- **Touch targets:** Prev/next arrows use `icon-lg` (48px); year buttons use `size="default"` + `min-h-12` (48px) to meet kid-friendly guidelines
- **Scroll behavior:** `scrollIntoView` replaced with targeted `container.scrollTo()` inside `requestAnimationFrame` to avoid unintended ancestor scrolling and DOM timing issues
- **Ref optimization:** Year button refs managed via `useCallback`-wrapped helper instead of inline closures
- **Attendance formatting:** Now displays K/M dynamically with a fallback to `toLocaleString()` for values under 1000
- **Button component:** Added `icon-lg` size variant (`h-12 w-12`)
- **MatchesSlide filter:** Year dropdown now only shows years that have match data (5 tournaments) instead of all 22
- **RecordsSlide clarity:** "Matches Recorded" subtitle now shows "From N featured cups" to clarify the mixed data granularity
- **Docs:** JSDoc restored for `TimelineSlide`, `TournamentCard`, and `StatBox`; `replit.md` updated

## Updates Since Last Revision

**Round 1** — Addressed critical/medium feedback from automated reviewers (coderabbitai, kiloconnect, devin-review):

| Fix | Detail |
|-----|--------|
| Year button touch targets | `size="sm"` (32px) → `size="default"` + `min-h-12` (48px) |
| Ref callback perf | Inline `ref={(el) => {...}}` → `useCallback`-wrapped `setButtonRef` |
| DOM measurement timing | Bare `useEffect` → wrapped in `requestAnimationFrame`; uses `offsetLeft` instead of `getBoundingClientRect` |
| Attendance edge case | Added `>= 1000` guard so small values don't render as `"0K"` |

**Round 2** — Addressed Devin Review yellow flags:

| Fix | Detail |
|-----|--------|
| MatchesSlide dropdown | Changed from `getAllYears()` (22 years) to new `getMatchYears()` (5 years with match data) so users only see filterable years that produce results |
| RecordsSlide mixed granularity | Added `matchTournamentCount` to `computeStats()`; subtitle now reads "From 5 featured cups" (localized in en/pt/ru) to clarify that match-level stats cover fewer tournaments than the 22 in tournament-level stats |

🚩 **scrollIntoView may cause unintended page-level scrolling**

The `scrollIntoView({ behavior: "smooth", block: "nearest", inline: "center" })` call at line 22 will scroll *all* ancestor scrollable containers to bring the button into view, not just the immediate overflow container (`scrollRef`). 🟡 **Missing requestAnimationFrame cleanup in useEffect causes stale callback execution**

The `useEffect` at `client/src/slides/TimelineSlide.tsx:32-41` schedules a `requestAnimationFrame` but never cancels it in a cleanup function. If `selectedYear` changes rapidly (e.g., user clicking next/prev quickly), multiple rAF callbacks queue up and fire sequentially, each calling `container.scrollTo()` with different targets, causing jittery/conflicting scroll animations.

<details>
<summary>Root Cause and Impact</summary>

The `useEffect` should return a cleanup function that calls `cancelAnimationFrame(rafId)` to cancel the pending frame when `selectedYear` changes or the component unmounts:

```js
useEffect(() => {
  requestAnimationFrame(() => {  // rafId not captured
    // ... scroll logic
  });
  // no cleanup returned
}, [selectedYear]);
```

When a user rapidly clicks through years, each click triggers a new `useEffect` which schedules a new rAF, but the previous rAF is never cancelled. This results in multiple scroll operations competing against each other. While the null checks (`if (btn && container)`) prevent crashes on unmount, the lack of cancellation means stale scroll targets still execute.

**Impact:** Rapid year navigation produces jittery, conflicting smooth-scroll animations instead of cleanly scrolling to the latest selected year.

</details>

```suggestion
  useEffect(() => {
    const rafId = requestAnimationFrame(() => {
      const btn = buttonRefs.current[selectedYear];
      const container = scrollRef.current;
      if (btn && container) {
        const scrollTarget = btn.offsetLeft - (container.clientWidth / 2) + (btn.offsetWidth / 2);
        container.scrollTo({ left: scrollTarget, behavior: "smooth" });
      }
    });
    return () => cancelAnimationFrame(rafId);
  }, [selectedYear]);
```
